앤트로픽이 인공지능 클로드를 써서 오픈소스 소프트웨어 123개 라이브러리에서 버그를 대규모로 찾아냈어요. 기존 테스트로는 놓치던 보안 취약점까지 발견했대요.


▶ 어셈블리 수준에서 수학적으로 증명한다는 게 뭔가요

형식 검증은 프로그램을 수학으로 모델링한 뒤, 코드가 정해진 규칙을 항상 따르는지 증명하는 방식이에요. 클로드는 컴파일된 RISC-V 어셈블리 코드 수준에서 이 작업을 했는데, 이렇게 어셈블리 단계에서 실제 운영 환경 소프트웨어를 대규모로 검증한 건 처음이라고 해요.


앤트로픽과 정리증명 전문 회사 시어럼이 손을 잡았어요. 구글의 오픈소스 테스트 프로젝트인 'OSS-퍼즈'에 등록된 라이브러리들을 대상으로 삼았고, 64MB 미만 입력에서 테스트가 충돌 없이 정상 종료되는지를 증명했습니다. 생성된 증명은 로크(Loch)라는 정리증명 도구 형식으로 기록됐는데, 무려 1억 8000만 줄에 달했어요.


▶ 클로드가 찾은 버그, 어떤 수준인가요

압축 해제 프로그램에서는 약 2000만 바이트 크기의 입력과 특정 데이터 배치가 맞아떨어져야 생기는 카운터 언더플로를 발견했어요. 이미지 디코더에서는 약 6400만 바이트 입력과 2GB가 넘는 메모리가 필요한 범위 밖 읽기 오류도 찾았습니다.


XML 파서 라이브러리 libexpat에서는 깊게 중첩된 입력으로 나타나는 CVE-2026-56132 취약점을 다시 발견했어요. 더 놀라운 건 일부 핵심 소프트웨어에서는 10년을 넘게 숨어 있던 논리 오류도 확인됐다는 거예요. 널리 쓰이는 PDF 리더를 검증했을 땐 불과 일주일 만에 통상 1년에 보고되는 수준의 보안 버그를 발견했습니다.


▶ 검증이 모든 경우를 다 커버하나요

이번 증명은 64MB 미만 입력을 전제로 해요. RISC-V 프로세서에서 실행되는 단일 스레드 정적 바이너리이며, 리눅스 운영체제와 고정된 메모리 예산 같은 특정 조건을 가정한 거죠. 평균적으로 한 증명은 약 1만 8000개 RISC-V 명령어로 구성된 바이너리를 대상으로 하고 60만 줄의 증명 코드를 포함했어요.


다만 검증하지 않은 테스트 진입점이나 다른 프로세서·운영체제 환경에서 나타나는 문제는 보장하지 않는대요. 로크의 증명 검사기가 증명이 명세를 충족하는지 자동으로 확인하기 때문에 사람이 일일이 검토할 필요는 없어요.


▶ 이번 프로젝트에서 얻은 다른 성과들

앤트로픽은 오픈소스 라이브러리 검증 외에도 여러 성과를 냈어요. 리눅스 커널에 포함된 zlib 압축 구현이 기술 명세를 따르는지 바이너리 수준에서 증명했고, 러스트로 만든 파이썬 인터프리터가 기존 CPython과 같게 동작하는지도 검증했습니다. 무작위로 생성한 파이썬 프로그램 170만 개 이상을 실행한 결과, 99.95%에서 CPython과 똑같이 작동했어요.


최신 모델인 오퍼스 5.5(Opus 5.5)는 36개 검증 과제 중 절반을 이전 모델인 오퍼스 5보다 약 40% 적은 토큰으로 해결했어요. 여러 AI 에이전트가 서로의 증명을 나눴을 때는 개별 작업할 때보다 토큰 사용량이 17% 줄어들었습니다. 앤트로픽은 생성한 증명 일부와 검증 모델을 공개했고, 협력사 시어럼도 다른 오픈소스 프로젝트에 같은 검증 절차를 적용할 수 있도록 지원 중이에요.
