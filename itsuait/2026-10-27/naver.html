② 사진저장 → 공유 시트에서 '이미지 저장'. 또는 사진을 길게 눌러 '사진에 추가'
③ 본문 (태그 포함)

마이크로소프트가 .NET 8, 9, 10과 .NET 11 RC3을 위한 긴급 보안 업데이트를 공개했어요. 구글의 Brotli 압축 알고리즘에서 발견된 버퍼 오버플로우 취약점을 막는 게 핵심이에요.


▶ Brotli 취약점이 뭔가요

CVE-2026-111497이라는 번호가 붙은 이 취약점은 Brotli 압축 해제 알고리즘에서 발생해요. 버퍼 오버플로우가 일어나면서 인증되지 않은 공격자가 프로세스 메모리를 읽거나 손상시킬 수 있게 돼요. 정보 유출, 서비스 거부, 심지어 권한 상승까지 가능해요.


동시에 수정되는 취약점이 세 개 더 있어요. CVE-2026-114148은 리눅스 환경에만 영향을 주는데, .NET 타르볼의 소유권 메타데이터 문제예요. .NET 10과 11은 소스 빌드 타르볼만 해당하지만, .NET 8과 9는 ASP.NET Core 타르볼 배포판도 포함돼요. CVE-2026-70197과 CVE-2026-102870도 함께 패치되는데, 각각 SocketAsyncEventArgs 메모리 손상과 Blazor WebAssembly 디버거 문제예요.


▶ 누가 업데이트를 받아야 하나요

모든 플랫폼의 .NET 사용자가 Brotli 취약점 영향권에 있어요. 다만 실제 위험은 애플리케이션이 어떻게 압축 데이터를 처리하는지에 따라 달라요. ASP.NET Core 요청 압축 해제, HttpClient의 자동 응답 압축 해제, System.IO.Compression Brotli API를 통해 압축 데이터를 다루는 애플리케이션이 취약해요.


흥미로운 점은 요청 압축 해제와 자동 응답 압축 해제가 기본값으로 켜져 있지 않다는 거예요. 그래서 명시적으로 이 기능을 활성화하지 않은 대부분의 애플리케이션은 즉각적인 위험이 낮아요. 하지만 System.IO.Compression Brotli API를 직접 쓰거나 이에 의존하는 라이브러리가 있으면 여전히 위험해요. .NET Framework는 이번 취약점의 영향을 받지 않아요.


▶ 각 .NET 버전별 업데이트 버전과 방법

.NET 8은 8.0.33으로, .NET 9는 9.0.22로, .NET 10은 10.0.14로 올려야 해요. .NET 11은 RC3으로 업데이트되고, RC2를 쓰고 있었다면 RC3으로 바꿔야 이번 보안 패치를 받을 수 있어요. SDK와 런타임 모두 업데이트 대상이에요.


업데이트 방식은 애플리케이션 배포 방식에 따라 달라요. 프레임워크 종속 애플리케이션이면 먼저 해당 .NET 버전의 업데이트된 런타임을 설치한 뒤 애플리케이션을 다시 시작하면 돼요. 자체 포함 애플리케이션은 더 복잡한데, 업데이트된 런타임으로 다시 빌드해서 배포해야 해요. 호스트에만 런타임을 설치하면 애플리케이션에 번들로 포함된 런타임은 업데이트되지 않거든요. 컨테이너 환경이면 이미지를 업데이트된 런타임으로 다시 빌드해야 해요.


▶ 이 취약점이 .NET만의 문제일까요

절대 아니에요. Node.js, Python, Bun, Envoy, Istio 등 여러 소프트웨어 프로젝트가 이미 패치를 공개했어요. Apache Arrow도 영향받았고, FFmpeg도 특별히 제작된 JPEG XL 이미지를 통한 악용 가능성이 보도됐어요. FFmpeg는 이미지 메타데이터 압축 해제를 위해 libjxl 라이브러리를 사용하는데, 이를 통해 Brotli에 도달할 수 있거든요.


클라우드 환경의 노출이 특히 심각해요. 클라우드 환경의 91%가 이 취약점에 노출된 구성 요소에 의존하고 있어요. 82%의 클라우드 환경이 공개적으로 노출된 Node.js 인스턴스를 보유하고 있고요. 컨테이너화된 애플리케이션, 쿠버네티스 클러스터, API 게이트웨이, 리버스 프록시, 서버리스 워크로드, 클라우드 호스팅 웹 서비스 등에서 Brotli가 광범위하게 쓰이기 때문이에요.


▶ 지금 바로 업데이트해야 하는 이유

작동하는 악용 코드가 이미 존재하고 있어요. 마이크로소프트의 보안 자문에 따르면 현재 성공적인 공격에 악용되고 있다는 증거는 없지만, 악용 가능성은 높다고 평가했어요. 그래서 마이크로소프트는 가능한 한 빨리 업데이트할 것을 권장해요.


패치를 적용할 때까지 임시 대책도 있어요. 신뢰할 수 없는 Brotli 압축 데이터를 차단하고, 영향받는 배포를 다시 빌드해서 서비스를 다시 시작하는 거예요. 하지만 이건 임시 조치일 뿐, 정식 패치를 적용하는 게 가장 확실한 방법이에요.
