구글 클라우드가 AI 에이전트 전용 컴퓨팅 서비스를 내놨어요. 각 에이전트를 독립적인 가상 환경에서 실행해 코드 실행이나 브라우저 조작 중 생기는 보안 위험을 막는 게 목표예요. 제미나이에 먼저 적용되고 수개월 내 고객용 프리뷰로 공개될 예정이에요.


▶ 마이크로VM으로 에이전트를 완전히 분리하는 방식

에이전트 컴퓨트 엔진의 핵심은 각 에이전트마다 전용 마이크로VM을 따로 할당하는 거예요. 각 가상머신은 자기만의 게스트 커널과 루트 접근 권한을 가지고 있으면서도 클라우드 하이퍼바이저를 통해 다른 실행 환경과 완전히 분리돼 있어요. 컨테이너처럼 하드웨어를 효율적으로 쓰면서도 기존 가상화 수준의 보안을 제공하는 구조랍니다.


마이크로VM은 무상태 구조로 돌아가기 때문에 별도 장비에서 구동되며, 고객 에이전트가 쓴 파일을 영구 저장하지 않아요. 저장되는 데이터도 불변 파일 시스템에만 보관되기 때문에 수정하거나 삭제할 수 없어요. 이렇게 설계한 덕분에 한 에이전트의 문제가 다른 에이전트에 영향을 주지 않게 돼요.


▶ 보안 칩과 샌드박스로 다층 방어 체계 구축

구글은 티타늄이라는 하드웨어 보안 아키텍처와 인프라 처리 장치를 활용해 보안을 강화했어요. 타이탄 보안 칩으로 펌웨어가 손상되지 않았는지 검증하고, 중앙처리장치에는 사이드채널 공격을 완화하는 기능을 넣었어요.


에이전트의 작업 실행 환경과 모델을 부르는 제어 영역을 따로 분리한 게 특징이에요. 모델을 호출하고 작업을 지시하는 하네스는 샌드박스 바깥에서 작동하고, 코드·셸 명령어·브라우저를 실행하는 환경에만 필요한 명령을 전달해요. 외부 프록시와 정책 검사를 통한 통제로 프롬프트 인젝션 같은 위협으로부터 내부 비밀정보와 시스템을 보호하는 거예요.


▶ 대기 시간 활용해 자원 효율을 극대화

에이전트는 도구를 실행한 뒤 모델의 응답을 기다리거나 사용자 입력을 기다리는 시간이 많아요. 이 대기 시간에 실제 컴퓨팅 자원이 낭비되지 않도록 설계했어요. 에이전트가 도구 실행을 마치고 대기 상태에 들어가면, 마이크로VM을 체크포인트로 저장한 뒤 유휴 상태로 전환해요.


작업이 다시 시작되면 저장된 스냅샷으로 실행 환경을 복원하는 방식이에요. 여러 에이전트가 같은 운영체제 템플릿을 쓸 때는 쓰기 시 복사 기법으로 메모리를 공유하고, 각 마이크로VM에는 하이퍼디스크라는 구글 클라우드 영구 디스크 서비스를 연결해 작업 맥락을 유지해요.


▶ 오픈소스 버전과 통합 관리 기능도 함께 제공

구글은 쿠버네티스 기반 환경에서 에이전트를 운영하려는 기업을 위해 에이전트 서브스트레이트라는 오픈소스 실행 환경도 준비했어요. 클로드 코드, 오픈클로, 헤르메스 등 다양한 에이전트 프레임워크와 연동되며, 마이크로VM이나 지비저 샌드박스를 이용해 에이전트별 실행 환경을 격리해요. 구글의 벤치마크에 따르면 에이전트 20만 개를 대상으로 초당 500회의 활성화를 처리했고, 일시 중단과 재개에 걸리는 시간은 500밀리초 미만이었어요. 기존 방식 대비 최대 10배 높은 컴퓨팅 밀도를 기록한 거예요.


기업 내 여러 AI 에이전트를 통합으로 관리하는 거버넌스 기능도 넓혀가고 있어요. 에이전트 게이트웨이, 레지스트리, 아이덴티티, 옵저버빌리티를 통해 에이전트가 여러 모델과 도구에 접근할 때 생기는 권한 오남용과 데이터 유출을 체계적으로 통제해요. 앞으로 몇 달 안에 토큰 사용량 관리와 모델 라우팅 기능이 추가되고, 핑 아이덴티티, 세일포인트, 사비언트 같은 외부 인증 서비스와도 연동할 예정이에요.
